# Blog Brief

Create a concise but actionable blog brief before writing.

## Brief Structure

Produce:

```markdown
# Content Brief: [Working Title]

## Angle
[Specific thesis and why this post should exist.]

## Audience
[Who it is for and what they already know.]

## Search Intent
[Informational, commercial, navigational, project discovery, technical how-to.]

## Keywords
- Primary:
- Secondary:
- Questions:

## Outline
1. Introduction / hook
2. Problem
3. What was built or argued
4. Technical detail / evidence
5. Results, limitations, or tradeoffs
6. How to try it
7. FAQ or closing section

## Evidence Plan
| Claim | Source Needed | Status |
| --- | --- | --- |

## Visual Plan
- Hero/banner:
- Inline screenshots:
- Tables/charts:

## Internal Links
- [anchor] -> [site path]

## Publish Checklist
- Frontmatter
- Images
- Build
- SEO check
```

## Rules

- Favor first-hand assets: local repos, screenshots, benchmark JSON, README sections, and prior posts.
- For project posts, inspect the project repo before finalizing the angle.
- Keep briefs short enough to execute immediately.
